# 文字过滤（黑白名单）

> **一句话**：发送设置里的文字过滤怎么决定「这张图带不带文字」，模式、关键字语法、匹配对象、配置键与日志全写在这。

## 1. 解决什么

相册里一批图往往混着截图、表情、导出的聊天图。用户要的是「图照发，文字别带」或者「只给名字对得上的那几张带文字」，
而现在只有全带或全不带两种极端：关掉功能就一张都不带，开着就每张都带。

文字过滤就是在这条链路上加一道闸：**图片照原样按顺序发出，只是那一行文字被单独拿掉**。
所以被筛掉的图不发文字、也不在聊天里留空行 —— 它跟「本来就没开功能」那张图看起来完全一样。

## 2. 判定插在哪（这是本功能唯一的实现难点）

判定必须落在 `textFor` 里、`RepeatCounter.bump` **之前**。原因是计数器按「这个名字第几次发」累加：

| 步骤 | 位置 | 如果判定放在它后面会怎样 |
| --- | --- | --- |
| 取名字 | `labelOfEntry` | — |
| 套重命名 | `RenameRules.apply` | — |
| **过滤判定** | `textAllowed(label, original)` | — |
| 加重复后缀 | `repeat.bump` → ` +2` / ` +3` | 被筛掉的图也涨了计数，下一张同名的图凭空跳号 |
| 发送 | `sendLabel` / `UiSender.send` | — |

换句话说是「**算了不算数**」的那个老坑：计数一旦加上去就撤不回来，因为 ` +N` 已经在别的图上发出去了。
所以过滤返回空字符串之前直接 return，`bump` 一次都不会跑。

空字符串是这里约定的「这张图不带文字」信封：

| 出口 | 见到空字符串的行为 |
| --- | --- |
| `startReplay` 主循环 | 不打 `sendLabel`，只记一行 `filter: text#N skipped by rules` |
| `flushFallback`（兜底队列） | 跳过 `UiSender.send`，只记一行 `filter: fallback label#N skipped by rules` |
| `batchTexts` 缓存 | 存的是空串，同一张图在这一批里取几次都只判一次 |

两个出口都**不调 `noteSent`**：没发出去的文字不该进记录页，也不该占「第几次」。

## 3. 三种模式

| 模式 | 配置值 | 命中关键字 | 没命中 |
| --- | --- | --- | --- |
| 关闭（出厂默认） | `off` | 带文字 | 带文字 |
| 白名单 | `white` | 带文字 | **只发图** |
| 黑名单 | `black` | **只发图** | 带文字 |

取值认不出来（旧版本写坏的、手改错的）一律当 `off`：多带一行文字，比整批图突然没名字更像「没装这个功能」。

设置页只暴露**两档**（关 = 白名单，开 = 黑名单）：`off` 留作老配置的兼容值，
进到这一页时如果读到 `off` 就自动写回 `white` —— 空关键字表本来就全部放行，
这一步不改变任何一张图的发法，但能让开关位置与真实行为对上（否则开关显示「关」、
配置却还是 `off`，用户接着加关键字会以为不生效）。

## 4. 关键字写法

存盘格式是一行一条：首尾空白自动去掉，空行跳过，`#` 开头是注释（想筛 `#` 开头的名字，把关键字写成别的能命中的片段）。
界面上是一条一条加的（§7），`#` 注释行只能靠导入备份写进去。

| 写法 | 判定方式 | 例 |
| --- | --- | --- |
| 不含 `*` `?` | **子串包含** | `033` 命中 `003033`、`微信截图_033` |
| 含 `*` 或 `?` | **整段通配**（`*` 任意多个字，`?` 一个字） | `IMG_2026*` 命中 `IMG_2026-11-10`，不命中 `my IMG_2026` |

整段通配的意思是两头要自己补星号：写 `Screenshot*` 只匹配以它开头的整串，中间出现就不算。

不让用户直接写正则：手写正则漏一个转义整表就废了，通配只留两个符号，转义在这里做，写错最多是不命中。

大小写开关（默认开）同时作用于子串与通配，中文不受影响 —— 它主要是给 `IMG_` / `screenshot` 这类英文名用的。

## 5. 匹配对象

判定拿到两段文本，任意一段命中就算命中：

| 段 | 内容 | 为什么要有 |
| --- | --- | --- |
| 发送文字 | 重命名规则套完、加 ` +N` 之前的最终名字 | 用户看到什么就筛什么 |
| 原文件名 | 相册条目原名去掉扩展名 | 重命名会把 `003033` 改成「截图」，按旧名筛的那批关键词才不会一夜失效 |

「原文件名」这一段可以用开关关掉（`img_label_filter_match_original`，默认开）：
给名字敏感的人一个退路 —— 只看发出去的文字。

注意后缀 ` +N` **不参与判定**：判的是名字本体，` +2` 是结果不是输入。

## 6. 失败即放行，空表不吞批

- 关键字表解析出任何异常 → 当成空表，不抛。
- 空表时**白名单也放行**。这是刻意的：用户刚切到白名单还没填规则，如果按纯语义执行，整批图的文字会瞬间全没，看着像功能坏了。
  真正要「一张都不带」的用法是关掉功能。

## 7. 设置页

入口在「发送设置 → 黑白名单」，行副标题就是当前状态（`白名单 · 3 条关键字` / `黑名单 · 12 条关键字`），点行进三级页。
整页三节（名单 / 匹配方式 / 关键字），关键字那一节里是两张卡 —— 一张列表、一张动作。**全部即改即生效，没有保存按钮**：

| 分区（SmallTitle） | 内容 |
| --- | --- |
| 名单 | 一个开关：**关 = 白名单，开 = 黑名单**。行副标题跟着开关换一句话，说清此刻会怎么发 |
| 匹配方式 | 忽略大小写、连原文件名一起匹配两个开关（整行可点，副标题只写「关掉就只看重命名后的文字」这种状态） |
| 关键字 | **卡一（规则列表）**：一条一行，每行是规则原文，右端 ✕（`AppIcons.Close` 细描边、40dp 触控区、贴右缘）删掉这一条；列表为空时这一行退化成占位说明。**卡二（动作，与卡一之间 12dp）**：「新建关键字」（行尾 `AppIcons.PlusThin`，与 ✕ 同画布同笔画）从屏幕底部弹出输入弹层（输入框 + 取消 + 确定），下面「清空关键字」（仅列表非空时出现） |

- **黑白名单做成开关，不用下拉**：本来就是二选一，开关的当前位置一眼可读，也省掉一次点击。
- **没有「保存」这一步**：新建、删单条、清空都是即写即存，`img_label_filter_rules` 每次变动立刻落盘，微信进程 3 秒内跟上。
- **删除只摘那一行**：按规则原文在表里定位、只移除这一行，`#` 注释行与其它行原样留着；新建追加到表尾，已有同一条时给 Toast 而不是重复写。
- **新建走贴底输入弹层**（`TextInputDialogSpec`，见 `docs/UI.md` §4）：输入为空时在框下报「关键字不能为空」，弹层不关。
- **清空先确认**：清空走贴底确认弹层（`ConfirmDialogSpec`），说明里写清清空后两种模式各自会发生什么 —— 它不是可撤销动作，不能点了就走。
- 动作结果反馈走 Toast（与「发送记录」页同口径），不在页面里堆状态文字。
- **卡里不放解释性注释**：名单语义已经在开关副标题里，卡内不再挂「只影响文字，图片一律照发」这类说明行（`docs/UI.md` §7 第 8 条）。
- **行与行之间不画线**：列表与动作行用「拆成两张卡」分隔，不用 `HorizontalDivider` —— 本仓所有页面都没有卡内分隔线，`start = 16.dp` 的短线从卡内缩进处起笔，看着像一条分叉（`docs/UI.md` §7 第 9 条）。

## 8. 配置键

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `img_label_filter_mode` | String | `off` | `off` / `white` / `black` |
| `img_label_filter_rules` | String | 空 | 一行一条的关键字表 |
| `img_label_filter_ignore_case` | Boolean | `true` | 忽略大小写 |
| `img_label_filter_match_original` | Boolean | `true` | 是否把原文件名也算一段判定文本 |

四个键都进 `ConfigKeys` 的 `ALL_KEYS` / `FEATURE_PARAM_KEYS` / `SNAPSHOT_KEYS` / `DEFAULTS`：
跟着备份走、能被重置回默认、微信进程能读到。它们**不进 `FEATURE_KEYS`** —— 那组的语义是「默认关掉的功能总开关」，
而这里的默认值 `off` 已经等价于关闭，模式值本身也不该按布尔默认值校验。

配置改动走既有通道：模块进程写 remote preferences，微信进程每 3 秒重新附着一次，**不用重启微信**。

## 9. 日志

排障时按这四行看（日志通道与其它功能一致）：

| 日志 | 含义 |
| --- | --- |
| `filter: rules=N ignoreCase=…` | 关键字表现解析出 N 条（改表后第一次判定时打一行） |
| `filter: drop mode=… label=… hit=…` | 这张图被筛掉，`hit` 是命中的那条关键字原文 |
| `filter: text#3 skipped by rules` | 主链路第 3 张没带文字发出 |
| `filter: fallback label#2 skipped by rules` | 兜底队列第 2 条没带文字发出 |

看不到 `filter: rules=` 说明这一批根本没走到判定：模式是 `off`，或者功能总开关没开。

## 10. 边界

- **只筛文字，不筛图片**：被过滤的图照样按原顺序发出去，只是没有那一行名字。本功能不做「跳过某张图」。
- 判定用的是发送那一刻的最终文字：发完再改重命名规则或关键字表，不会回溯已经发出去的东西。
- 通配是整段匹配，`Screenshot*` 不会命中 `my Screenshot_1`。
- 一次判定最多 2 段文本 × N 条规则，且每张图每批只判一次（结果进 `batchTexts` 缓存），几百条关键字也不影响发送节奏。
